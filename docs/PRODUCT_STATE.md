# RHOOK product state

## Product goal

Provide Counterfactual Execution through the existing SDK: a developer selects a
supported Hookr scenario, RHOOK obtains authenticated state, executes separate
BASELINE/VARIANT worlds, and returns verified comparison records. Hookr LaunchLab
will be an interface to this SDK, not another execution engine.

## Confirmed capabilities

Source-only installation, case import/planning, bounded acquisition and native
orchestration exist. An installed `scenario-close` completed one private local
fresh-checkpoint LP100/LP50 acceptance: discovery2, a frozen witness, fresh
offline2 with `Source=nil`, recorded verification/comparison and confirmed
cleanup. All four action receipts succeeded and all ten declared deterministic
comparison fields matched. Acquisition used59/64RPC,9.202s and1,503,168 response/
header bytes. See the [scope and limitations](../sdk/SCENARIOS.md#installed-on-demand-acceptance).

Build09's earlier full scenario used a laboratory launcher. Build12 separately
reproduced a prepared witness through `ExecutionSDK`. Build26D/27g concern
historical ACTUAL/BRANCH recorder-only replay. These are distinct milestones.
All named Hookr cases use Go/Nitro; `qualifiedClaims=0` and general witness
coverage remains `UNKNOWN`.

## Current product limits

One local acceptance establishes neither reliability across checkpoints nor a
general state-acquisition service. The supported buy is still fixed0.001ETH at
one pinned pool. Private runtime/witness distribution, independent external
native reproduction, broader transaction parameters and current-generation Hook
Block adapters remain separate work. The source clone alone is not a complete
native runtime and never substitutes recorded receipts for execution.

## Next verifiable capability

Prepare a versioned, narrowly bounded transaction-amount capability while
preserving the existing fixed profile. Bind the amount into plans, signed action,
operation/evidence commitments and native admission. It requires separate design,
implementation, worker qualification and exact execution authorization. No
arbitrary transaction/state-write/pool interface or speculative Hook Block
support is implied. Do not rerun the accepted LP50 case merely for publication.
No live/native execution or publication is granted by this document.
